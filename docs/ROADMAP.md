# Ecosystem roadmap

This is a working list of extension directions, not a release schedule. Proposals should start with a concrete user problem and acceptance criteria; maintainers can revise priority based on reproducible reports and contributor capacity.

## Implemented foundation

The current board parses local Claude Code and Codex rollout transcripts and exposes local snapshots and a message bus. Codex sessions have provider selection, measured models, linked native children and bounded read-only conversation; see [Codex sessions](CODEX_SESSIONS.md). The message bus does not inject messages into Codex. The message CLI can fall back to `.team/inbox` files when the board is unreachable. Tests exercise synthetic transcripts, temporary-home installation and local HTTP behavior. Contributor instructions and review prompts are available in [AGENTS.md](../AGENTS.md) and [the Codex maintenance guide](CODEX.md).

Implemented extension tools include the [versioned aggregate snapshot export](INTEGRATIONS.md), a [Prometheus textfile export and node_exporter recipe](INTEGRATIONS.md#prometheus-and-node_exporter), a [self-contained SVG battle card](INTEGRATIONS.md) rendered from an offline snapshot or the loopback board, a [single-file offline HTML replay](INTEGRATIONS.md#offline-replay) of one desensitized snapshot, a [Codex exec JSONL metrics adapter](CODEX_METRICS.md) with synthetic fixtures, and a [read-only no-account board demo](DEMO.md). The same synthetic board is also static files in [`docs/site/`](site/index.html), for a browser that does not run Python. GitHub Pages publishes that directory after Settings → Pages uses GitHub Actions. The Prometheus output has fixed labels and atomic file replacement; monitoring services remain separately managed. The battle card draws only fields that snapshot already contains, including a stall-alert count, theater count, or retained live-hook count when those fields are present, and a session budget-utilization bar when `budget.ratio` is set. `--session` and `--project` select a loopback snapshot the same way the aggregate export does. The exec adapter is an offline event summary, with its supported format and limits documented separately. The board also reads Bash test commands from the transcript (pytest, `python -m unittest`, npm/pnpm/yarn test, go test, cargo test, and the jest/vitest/mocha output those scripts often print). The latest result is a pass, fail or unknown badge on the member and, when an official task's `owner` is exactly that member's name, on the task. Truncated output and a summary that disagrees with the exit status stay unknown. A failure turns the card red; the badge scrolls to that activity row. Prometheus can count those latest results when they are present. The board also shows a read-only kanban of the official Agent Teams task list for the selected session (`~/.claude/tasks/<team>/`), refreshed through the existing snapshot poll. Hover or focus links a card to the member or lead only when `owner` is that exact name. A plain click or Enter opens a read-only detail drawer; Alt-click or the pin control pins the highlight. See [AGENT_TEAMS.md](AGENT_TEAMS.md). When the selected session's directory is a git checkout, each official task card can also show the tracked file count and insertions/deletions for that task's in-progress window, or the current branch/worktree diff when the task has no clock. `.team/tickets` rows use the files named in the ticket. Git is invoked read-only, with hooks, optional index locks, and external diff drivers disabled. If git is missing, the path is not a repository, or the command fails, the card omits the number instead of showing zero. Idle, stalled or errored members who have been quiet for at least 10 minutes (configurable) raise a dismissible alert in the header and tab title; the page asks for desktop notification permission only from that alert's own switch. See [DEMO.md](DEMO.md). `python install.py --hooks` can also register Claude Code `PreToolUse`, `PostToolUse`, `SubagentStop`, `Notification`, and `Stop` hooks. `hook_relay.py` posts a short loopback event; the board keeps a bounded in-memory list and joins it into the transcript activity feed so one tool call is one row. The key is session plus `tool_use_id`, or tool name, a five-second window and an input fingerprint when the id is missing. `live.merged` is true once that join runs. Estimated cost still comes only from transcript usage. See [HOOKS.md](HOOKS.md). Sessions that share a git repository across worktrees are grouped into one theater with a branch per session; the assumptions are in [WORKTREES.md](WORKTREES.md). A `budget` block in `team.json`, or `--budget` at startup, adds an estimated-cost guard for that session. With no budget the guard stays hidden. Near the cap it turns yellow, over the cap it turns red, and it names a lower tier from the role table. Unpriced models stay a lower bound. When that session cap is set, the Prometheus textfile also exposes `claude_agent_team_budget_utilization_ratio{scope="session"}`. A `cacheAdvice` block in the same file sets the hit-rate threshold and the cache TTL. When a member or the lead is under that hit rate, the cost rank can list a cause the transcript actually shows (repeated cache writes, a gap longer than the TTL, a system-prompt or tool-list change, model switching, or one-shot subagent cold starts) together with an estimated saving from the price table. Thin signals produce no line. `cacheAdvice: false` turns the block off.

`tools/retro_report.py` writes a Markdown retrospective from `--demo`, an offline snapshot, or the loopback board. It copies timestamps, estimated cost, tokens, stalls, blocked tasks and parsed test results only when those fields are present. A null price is 未知, and a positive `unpriced` count marks that object's numeric cost 部分. It does not sum a missing total, invent an idle age, or estimate cache savings.

`tools/export_otel.py` writes one OTLP/JSON trace file from `--demo`, an offline snapshot, or the loopback board. It copies timestamps, estimated cost, token counts, and parsed test fields only when those fields are present. A null cost is omitted. A member with no end time does not get a span. The file is not uploaded. The OTLP subset and the Langfuse / Phoenix import commands are in [INTEGRATIONS.md](INTEGRATIONS.md).

`tools/release_check.py` is the repeatable pre-release check in [RELEASE_CHECKLIST.md](RELEASE_CHECKLIST.md). It compares `VERSION` with the latest changelog section, requires notes under the unreleased heading, checks that script files cited from the READMEs exist, runs `tools/build_pages_site.py --check` when that command exists, and checks that `tests/` can be discovered. The report is a pass/fail table; `--json` prints the same result; a failure exits non-zero. The command does not create a tag or a GitHub Release. Supported interpreter and OS combinations remain the matrix in `.github/workflows/test.yml`. User-configuration preservation remains the install and update tests. A compatibility claim still requires those checks to pass. CI runs the script as its own job and does not make the matrix wait on it.

The synthetic tree in [`examples/agent-teams.synthetic/`](../examples/agent-teams.synthetic/README.md) reproduces that command room offline: a blocked dependency chain, the same task id in two files, mixed TaskList and TaskGet shapes, and a teammate whose name matches no task owner. Tests reject credential-like strings, absolute home paths, email-shaped text, and `sk-` / API key patterns under `examples/`. The over-2MB skip uses a temporary file generated during the test. The planned shared collection below still applies that bar to every future fixture family.

## Planned work

| Priority | Direction | Acceptance criteria before calling it supported |
| --- | --- | --- |
| 1 | Broader transcript compatibility | Extend observed Codex rollout coverage and future adapters using synthetic fixtures; test session selection, identity, tool events, errors and usage deduplication; preserve Claude Code behavior. Current limits are documented in CODEX_SESSIONS.md. |
| 1 | A shared, privacy-safe fixture collection | Every fixture is synthetic or explicitly sanitized; contributors can reproduce the target bug offline; tests reject accidental inclusion of credentials, local identities and private transcript content. |
| 2 | More extension recipes | Demonstrate a specific consumer using the documented integration surface; document input/output shape and failure behavior; include an offline example and avoid requiring access to a maintainer's machine. |
| 2 | Maintainer automation using Codex | Start with drafts for triage or review; define trusted inputs, permissions, secret handling, spending limits and human approval before posting, merging or releasing; include regression checks. No such hosted automation is currently configured. |
| Ongoing | Feedback from actual use | Reports include version, platform, redacted reproduction and expected outcome; changes link to an acceptance test or manual verification. Publish adoption metrics only when there is a verifiable source. |

## Propose an extension

Use the repository's feature-request form. Explain who needs the extension, one example input and expected output, privacy considerations and a small first increment. A proposal or roadmap row does not mean the feature exists. Each adapter's supported format and limits need explicit evidence; maintaining this repository with an agent alone is not integration evidence.

Implemented integration commands are documented separately in [INTEGRATIONS.md](INTEGRATIONS.md). Contribution and security reporting paths are in [CONTRIBUTING.md](../CONTRIBUTING.md) and [SECURITY.md](../SECURITY.md).
